# 初稿

用户给一个想法。先定**主题**（这篇要讲什么），再调研、再写初稿。**标题**按写成的内容后面再改，不要和主题混成一件事。不要编造亲身经历。目录：`.artifacts/drafts/<YYYYMMDD-主题>/`。

## 执行步骤

1. 若当天还没有这篇的目录：先问用户要不要创建拟用路径，确认前不要 mkdir、不要写稿。已有相近主题则沿用，不再问
2. 用户确认后，只使用锁定的那一个草稿目录。同一主题当天不会有第二个文件夹
3. 用一句话写下主题，写入该目录的 `topic.md`。之后调研和粘贴材料都必须对这个主题，跑题的不用
4. 没有 `research.md` 时跑 `topic-research`（本地素材 → collect.py → web_search → 深读），只留下能支撑主题的条目
5. 在聊天里说明写法和各节要解决什么。废水想法列入禁用
6. 写 `article.md` 初稿（大约 1200–2000 字）。H1 用工作标题即可，可以就是主题原句，稍后可改
7. `open_article` 定位 `article.md`
8. 初稿或改稿之后再给标题候选（≤25 字）。用户回复编号只改 H1，不改主题、不重写正文
9. 后来粘贴的一段话：先对照主题，一致才整理进稿

## 示例

```
/outline 做产品容易，走到客户很难
```
